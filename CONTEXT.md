# HDSAT — working context

Independent Digital SAT / PSAT practice app. React 19 + Vite frontend, static
build deployed to PythonAnywhere (`https://hdsat.pythonanywhere.com`), Supabase
for accounts and cloud sync, question bank generated by Python under
`supabase/import/`.

## Where things live

| Area | Path |
| --- | --- |
| App shell / navigation | `src/components/Layout.tsx` |
| Global state, cloud vs guest | `src/lib/store.tsx` |
| Guest persistence + coins | `src/lib/storage.ts` |
| Supabase data access | `src/lib/cloud.ts` |
| Full-test engine and plans | `src/lib/examEngine.ts` |
| Bluebook test runner | `src/pages/FullTest.tsx` |
| College Board highlight/notes | `src/components/HighlightableStimulus.tsx` |
| Math tools + reference sheet | `src/components/MathTools.tsx` |
| Auth email template + setup | `supabase/email-templates/` |
| Bank generators | `supabase/import/generate_bank_scale.py`, `generate_bank_rw_volume.py` |
| Generated bank | `src/data/questionBank.json` |

Checks: `npm run typecheck`, `npm test` (Vitest), `npm run build`. Database seed:
`cd supabase/import && python import_questions.py`. Deploy: `.venv/Scripts/python .pa/deploy.py`.

## Rules of the road

- Guest-first: everything works without an account; local data lives under
  `hdsat.profile.v1`.
- Cloud writes stay behind Supabase RPCs and RLS. Never ship a service-role key.
- New R&W items must be original, single-answer, and pass the importer's
  validation. Prefer genuinely distinct passages over duplicated variants.
- Full tests are strictly fresh-item unless the unseen pool runs out; the
  coverage notice must say so.
- Keep the Bluebook runner visually quiet (grey 1px rules, no rainbow banners).
